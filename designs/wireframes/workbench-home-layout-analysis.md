# 工作台首页：净回款诊断与行动闭环

## 定位

工作台首页面向运营负责人，以净回款为核心经营结果。它不复刻运营数据看板，也不把任务、系统状态和经营问题并列堆放，而是连续回答五个问题：

1. 本月净回款按当前节奏能否达成目标？
2. 结果由哪些经营结构和过程指标组成？
3. 哪个经营流程最需要先优化？
4. 今天和本周需要完成什么动作？
5. 上次调整是否产生了预期结果？

页面主线统一为：

`净回款结果 → 目标与预测差距 → 经营结构 → 过程诊断 → 流程优先级 → 行动 → 结果回看`

## 已确认的产品口径

- 核心结果：净回款。
- 主要使用者：运营负责人。
- 首版流程范围：流量、转化、客单、投放、退款。
- 重要不紧急事项不是首页重点。数据不足时停止生成建议，只说明缺失的数据及其用途。
- 交付形态：一套完整交互线稿，首页之外提供足够的下钻页面。

## 需要严格区分的三个数

| 指标 | 示例 | 含义 |
|---|---:|---|
| 当前累计净回款 | ¥11.08M | 统计结束日前已经发生的净回款 |
| 当前目标差额 | ¥13.22M | 月目标减当前累计净回款，不代表月末最终缺口 |
| 月末预计缺口 | ¥4.28M | 月目标减月末预测净回款，是首页的主要风险指标 |

首页不能把“当前目标差额”和“月末预计缺口”混称为目标缺口。预测必须展示预测方法、完整数据日和可解释的区间。

## 归因边界

### 可以直接展示

- 钉钉权威口径：月目标、当前净回款、GMV、退款、推广费、渠道 / 店铺结构、日趋势。
- 可解释计算：当前目标差额、完成率、按去年同期逐日回款分布计算的月末预测。
- PowerBI 已覆盖范围：访客、支付买家、支付转化、客单价、商品与推广表现。

### 只能作为诊断信号

- 支付转化和客单价若只覆盖部分平台或店铺，只能说明覆盖范围内的变化，不能直接解释全渠道净回款缺口。
- 渠道 / 店铺没有独立目标时，只能展示贡献结构、同比变化和风险信号，不能把公司总目标缺口强行分摊为渠道责任。
- “预计可挽回金额”必须存在计算公式、历史动作结果或人工确认，否则不展示。

### 当前不能判断

- 库存与供给承接：缺少可售库存、周转、缺货和预计到货。
- 未来活动准备：缺少活动日历、商品计划、价格权益版本和资源位。
- 内容提前布局：缺少素材发布 ID、素材版本与曝光 / 点击 / 转化回流。
- 客户经营：若缺少新老客、复购与会员数据，不生成客群建议。

## 页面结构

### 01 工作台首页

首屏用一句自然的经营描述和一组区分清楚的结果数字完成定调：

- 标题：工作台首页
- 描述：看业绩进度、找主要原因、安排下一步。
- 主要判断：按当前节奏，7 月净回款预计完成 82.4%，月末预计差 ¥4.28M。

首页展示：

1. 本月业绩进度。
2. 净回款构成与五个过程信号。
3. 流程优先级。
4. 今天和本周的行动。
5. 上次调整效果。
6. 暂不生成的长期建议及所需数据，降为页尾弱提示。

### 02 净回款缺口

回答“差多少、怎么算、哪些数字可以归因”：

- 当前累计、当前目标差额、月末预测和预计缺口。
- 实际回款与目标节奏曲线。
- 预测方法、完整数据日和预测区间。
- `GMV - 退款 - 其他调整 = 净回款` 的结果桥。
- 可直接归因、只能观察、暂不能判断的边界说明。

### 03 渠道 / 店铺 / 商品

回答“问题集中在哪里”：

- 渠道、店铺、商品三个可切换维度。
- 净回款、贡献占比、同比、退款率、费比。
- 所有排序都展示依据，缺少独立目标时不计算“渠道目标缺口”。
- 从异常实体继续下钻到退款、投放或转化页面。

### 04 流量与转化

回答“流量有没有转成支付”：

- 访客 → 加购 → 支付买家的漏斗。
- 支付转化和客单价的同口径变化。
- 覆盖范围和未覆盖渠道。
- 商品 / 渠道异常清单。
- 只有当覆盖完整且原因字段可用时才给出明确优化建议；否则生成核查任务。

### 05 退款治理

回答“退款为什么高、卡在哪个环节”：

- 退款金额、退款率、集中度和同口径变化。
- 商品 → 退款原因 → 售后环节的下钻。
- 原因字段完整度。
- 当前最紧急的流程问题、负责人和截止时间。
- 不将退款总额直接写成“可挽回金额”。

### 06 投放效率

回答“哪些计划需要核对或调整”：

- 推广费、费比、净回款 ROI。
- 渠道 → 计划 → 商品的下钻。
- 盈亏线规则、观察窗口和样本量。
- “暂停”“继续观察”“补证据”必须由规则和证据支撑。

### 07 流程优先级

回答“为什么先优化这个流程”：

- 优先级由结果影响、时间紧迫度、证据完整度、可控性共同决定。
- 每个评分都可以展开查看依据。
- 数据完整度不足的流程不会因为估算金额高而排在第一。

首版示例顺序：

1. 退款治理：全渠道数据可用，退款率明显变化，且原因字段和责任流程存在待补项。
2. 投放计划管理：费用数据可用，需要按计划核对盈亏线和观察窗口。
3. 转化诊断：存在下降信号，但 PowerBI 覆盖范围有限，先核查再决定动作。
4. 客单价：保持观察，不生成优化动作。
5. 流量：没有明显异常时不占用行动区。

### 08 行动详情

回答“这件事具体怎么收口”：

- 问题、对象、依据、负责人、截止时间。
- 建议动作和不处理的后果。
- 依赖与阻塞。
- 执行步骤和完成标准。
- 后续复盘指标、基线和观察窗口。

### 09 效果回看

回答“上次调整有没有用”：

- 调整前基线。
- 预期结果。
- 实际结果。
- 数据覆盖和观察窗口。
- 继续、调整、停止三种明确结论。

### 10 数据条件

回答“为什么暂时不给长期建议”：

- 当前可用、部分覆盖、缺失的数据。
- 每项缺失数据会支持哪类判断。
- 建议的最小数据结构、更新频率和责任来源。
- 数据未满足门槛前，不在首页生成重要不紧急事项。

## 首页文案规则

使用简短、直接、面向运营负责人的表达：

- 使用：本月业绩进度、差距主要来自哪里、先优化哪个环节、今天和本周先做、上次调整效果。
- 使用：查看计算、查看明细、核对原因、创建核查任务、指定负责人。
- 避免：拍板、经营敞口、运营指挥、守住金额、决策窗口、唯一中心等表演性表达。
- 不使用角色标签替代具体任务，不以内部方案名称 A / B / C / D 面向真实用户。

## 交互要求

- 所有首页结论都能进入对应下钻页。
- 左侧保留全站产品工作栏；工作台首页的下钻页使用可折叠子导航，首页默认收起，进入下钻页自动展开且允许手动收起。
- 面包屑和“返回首页”均可工作。
- 渠道 / 店铺 / 商品维度可切换。
- 证据抽屉展示口径、计算、数据源和限制。
- 流程评分可查看构成。
- 数据不足的建议入口进入数据条件页，不伪造建议。
- 1440、1280、1024、768、390、375 宽度下无页面根级横向溢出、文字截断和按钮挤压；导航和明细表允许在组件内部滚动。
