## 12. 审计结论

### 可直接采用的事实

- **q18 join key = `商家规编（后台）`**：8055 行全部非空、0 重复、0 维度冲突（SPU/床垫类别/厚度/是否折叠/尺寸 五维度）。直接 LEFT JOIN q26 不放大订单事实（行数、销售数量、商家实收三项差异均为 0）。计划里的"重复折叠 / ambiguous 冲突"逻辑在当前数据下不会触发，但保留作防御性兜底。
- **订单行覆盖率 90.1%**（117117/130020），超过 80% 阈值。尺寸/SPU 模块标记 coverage 即可，无需降级。
- **SKU 覆盖率 56.9%**（2156/3789 distinct 编码）。未匹配的 43% SKU 仅贡献 10% 订单行（长尾小单品），属正常。
- **SPU 映射率 90.1%**，110 个 distinct SPU，q18.SPU产品商编 全部非空。
- **价格 7 档分布合理**：有效行 100%（130020 行全部 商家实收>0 且 销售数量>0），无 excluded。档位集中在 1000–2000 区间。
- **尺寸格式**：颜色规格以 `\d+MM*\d+MM` 为主（如 `1800MM*2000MM`），少量 `*CM`（如 `180*200CM`）和三围规格（枕头 `70*40*18CM`）。q18.尺寸 字段为补充来源。标准化需统一分隔符 `×`、单位转 mm、宽×长排序。

### 重大风险：定制结构模块在当前数据下几乎无信号

颜色规格里的定制关键词极少：

- 定制/定做/非标：1 行
- 异形：0 行
- 缺角：0 行
- 折叠：3147 行（这是**产品属性**，q18 有独立 `是否折叠` 字段，不能作为定制信号）

参考看板的 7 类定制标签（定制尺寸/厚度/内材/折叠/异形/缺角/未填写）在当前数仓数据下**无法推导**。原因：参考看板很可能依赖 ERP 中一个未同步到数仓的原生"定制标签"字段，而颜色规格里几乎没有定制关键词。

**定制模块的降级方案（执行阶段采用）：**

1. 只做"常规订单 vs 折叠款订单"对比，折叠款用 q18.`是否折叠 = 是` 识别，不把折叠当定制。
2. 7 类标签仅保留实际有信号的（基本只有"未填写标签"兜底），其余标签固定返回 0。
3. 页面明确标注：`当前数仓无原生定制字段，定制结构仅基于折叠款属性与颜色规格关键词推导，不等同于参考看板口径。`
4. 若用户后续接入 ERP 定制字段，再替换推导逻辑。
