# 渠道质量数据分析报告体系设计

> 起草：数妙妙（Phoebe）/ DataAnalyticsReporter
> 日期：2026-08-03
> 范围：商品管理 → 渠道管理 → 渠道质量判断 模块的数据分析报告体系重构
> 目标：把现有"描述性快照"升级为"决策驱动型报告体系"，让每一张表、每一段结论都能直接回答业务决策问题。

---

## 一、现状诊断：为什么现有报告"不够深入"

现有渠道质量模块（`ChannelQualityPanel.tsx` + `channelQualityJudge.ts`）的产出是：1 张条形图 + 1 段 callout 文字 + 3 张明细表。从数据分析师视角，它存在 **7 个结构性缺陷**，每一个都直接导致"难以支持业务决策"。

| # | 缺陷 | 证据（现状） | 业务后果 |
|---|------|-------------|---------|
| 1 | **只有产出，没有投入** | callout 只看毛利率、退款率、件单价；`dt-channel-metrics.md` 里的 `spend`/`roi`/`feeRate` 完全未接入 | 算不出"花多少钱赚多少钱"，预算决策无依据 |
| 2 | **没有时间维度** | 全是当期静态快照，无环比/同比/趋势线 | 回答不了"这个渠道在变好还是变差"，无法预警恶化 |
| 3 | **没有漏斗** | `exposure`/`clicks`/`ctr`/`addToCart` 字段存在但未用 | 不知道"量从哪来"，无法定位是流量问题还是转化问题 |
| 4 | **没有目标对齐** | `target` 字段存在但未用 | 回答不了"达成进度、缺口多大、要不要追加投入" |
| 5 | **结论是描述，不是诊断** | "X 毛利率最高、Y 垫底，优先拆解促销" | 描述了 What，没回答 Why 和 So-what，没有量化机会 |
| 6 | **没有综合评分** | 决策者要逐行读 3 张表自己拼判断 | 无法一眼排序"哪个渠道该加投、哪个该收缩" |
| 7 | **没有置信度与边界** | 结论不区分"已验证"与"假设" | 决策者不知道该信几分、还缺什么数据 |

**一句话总结**：现有报告把数据"摆出来"了，但没有"算明白"。它缺少从数据到决策的**转化引擎**——投入产出闭环、时间趋势、健康度评分、机会量化。

## 二、设计原则

整套体系遵循四条原则，偏离任何一条都会让报告退回"描述层"。

1. **决策倒推，不是数据正推**
   先问"业务要做什么决策"，再倒推需要什么指标、什么对比、什么粒度。拒绝"有什么数据画什么图"。

2. **投入→漏斗→产出→目标 四段闭环**
   一个渠道的健康度必须同时看四段：花了多少（投入）→ 流量如何（漏斗）→ 赚了多少（产出）→ 离目标多远（目标）。任一段断裂，结论就不可信。

3. **分层供给，各取所需**
   执行层给结论、诊断层给证据、研究层给方法。老板不该读归因表，运营不该只看 KPI 卡。

4. **每条结论必须可执行**
   结论格式固定为：`现象 + 量化影响 + 根因(置信度) + 建议动作 + 预期收益 + 优先级`。不允许出现"建议关注"这种无动作表述。

## 三、数据资产盘点与缺口

### 3.1 已有但未充分使用的数据（关键机会）

| 数据段 | 字段 | 来源 | 现状使用 |
|--------|------|------|---------|
| 产出 | salesUnits / receivedAmount / grossProfit / grossMargin / refundRate / avgUnitPrice | channelBreakdown | 已用 |
| 产出 | mattressCategoryBreakdown / productNameOverview | 后端 | 已用 |
| **投入** | **spend（站内费额）/ roi / feeRate** | **dt-channel-metrics** | **未接入渠道质量模块** |
| **漏斗** | **exposure / clicks / ctr / addToCart / favorite** | **dt-channel-metrics** | **未接入** |
| **目标** | **target（渠道目标额）** | **dt-channel-metrics** | **未接入** |
| 时间序列 | dailyPlatforms / dailyStores（日粒度） | dt-channel-metrics | 未在渠道质量模块做趋势 |

> 这是最大的浪费：投入、漏斗、目标数据已经躺在 `local-data/` 里，渠道质量判断却完全没用。**第一步重构的核心，就是把这四段数据接进来。**

### 3.2 数据缺口（需要补采或标注）

| 缺口 | 影响 | 补法 |
|------|------|------|
| 成本匹配率明细 | 毛利率口径不稳定，部分渠道 grossMargin 为 null | 后端补 `matchedReceived / receivedAmount` 比率，低于阈值标记"成本不可信" |
| 促销活动标签 | 无法区分自然量与促销量，ROI 归因失真 | 接活动日历，标注每日是否促销、促销类型 |
| 客单价/件单价分层数据 | 无法判断件单价变化是结构变化还是定价变化 | 后端补 SKU 维度明细 |
| 渠道费用拆分（站内/站外/佣金） | 费比口径粗 | 与财务对齐费用科目 |

## 四、三层报告体系架构

```
┌─────────────────────────────────────────────────────────┐
│  L1 执行层 · 渠道决策看板（每日/每周）                       │
│  给：业务负责人 / 老板                                       │
│  答：今天哪个渠道该加投？哪个亮红灯？预算怎么调？              │
│  产出：健康度评分卡 + 预算建议 + 红黄灯                      │
├─────────────────────────────────────────────────────────┤
│  L2 诊断层 · 渠道质量月度诊断报告（每周/每月）                 │
│  给：渠道运营 / 品类运营                                     │
│  答：为什么这个渠道毛利掉了？机会在哪？风险在哪？               │
│  产出：5维度健康度 + 驱动拆解 + 机会量化 + 风险清单            │
├─────────────────────────────────────────────────────────┤
│  L3 研究层 · 专题分析（按需）                                │
│  给：数据 / 战略                                            │
│  答：促销到底值不值？渠道间是否互 cannibalization？增量多少？   │
│  产出：归因 / A/B / 增量测算 / 对标                          │
└─────────────────────────────────────────────────────────┘
```

### 4.1 L1 执行层 · 渠道决策看板

- **受众**：业务负责人、老板
- **频率**：每日自动刷新，每周一汇总
- **决策场景**：预算调配、异常干预、目标达成跟踪
- **核心组件**：

| 组件 | 内容 | 决策动作 |
|------|------|---------|
| 渠道健康度评分卡 | 每渠道 A/B/C/D 评级 + 总分 + 趋势箭头 | 一眼排序优先级 |
| 预算建议条 | "建议将抖音预算 +15%、唯品 -30%"，附预期增量 | 直接调投放 |
| 红黄灯预警 | 退款率突破阈值 / ROI 连续 3 日下滑 / 达成率落后 | 触发干预 |
| 目标达成进度 | 每渠道 GMV vs target，缺口金额 + 缺口天数 | 决定是否追加 |

### 4.2 L2 诊断层 · 渠道质量月度诊断报告（核心交付）

- **受众**：渠道运营、品类运营
- **频率**：每周一版快报，每月一版深度
- **决策场景**：根因定位、优化方向选择、目标对齐、风险前置
- **报告结构（固定 6 段）**：

```
1. 执行摘要      — 一句话主结论 + 3 条证据 + 置信度 + 头部建议
2. 健康度总览     — 5 维度雷达 + 评级 + 环比变化
3. 驱动因素拆解   — 毛利变动 = 量 × 价 × 结构 × 成本，逐项归因
4. 机会量化      — 每个优化机会的预期增量毛利 + 实现难度
5. 风险清单      — 退款恶化 / 毛利侵蚀 / 达成落后，按优先级排序
6. 建议与置信度   — 动作 + 预期收益 + 置信度 + 待验证假设
```

### 4.3 L3 研究层 · 专题分析

- **受众**：数据分析师、战略
- **频率**：按需触发
- **典型专题**：
  - 促销增量测算（增量 GMV / 增量毛利 / 费比盈亏平衡点）
  - 渠道间 cannibalization（A 渠道放量是否吃掉 B 渠道）
  - 渠道×品类矩阵（哪个渠道卖哪个品类最赚）
  - 退款归因（退款集中在哪些 SKU、是否渠道特异性）

## 五、指标体系

采用"北极星 + 驱动 + 护栏 + 目标"四层指标模型，避免堆砌。

### 5.1 指标模型

| 层级 | 指标 | 定义 | 决策意义 |
|------|------|------|---------|
| **北极星** | 渠道净毛利贡献 | grossProfit - 退款损失 - 渠道费用 | 渠道到底赚不赚钱 |
| **驱动·产出** | GMV / 商家实收 / 件单价 / 销量 | 产出规模与结构 | 量价结构 |
| **驱动·效率** | 费比 / ROI / 边际 ROI / 回款率 | 投入产出比 | 该不该继续投 |
| **驱动·漏斗** | CTR / CVR / 加购率 / 收藏率 | 流量效率 | 量从哪来、卡在哪 |
| **护栏** | 退款率 / 退款率 7 日趋势 / 毛利率底线 | 风险边界 | 触发干预 |
| **目标** | 达成率 / 缺口 / 缺口天数 | 目标对齐 | 是否追加投入 |

### 5.2 关键派生指标（必须新增）

- **边际 ROI** = ΔGMV / ΔSpend：判断"再投 1 元还能赚多少"，是预算调配的核心依据
- **增量毛利** = 优化后毛利 − 现状毛利：机会量化的统一口径
- **费比盈亏平衡点** = 使增量毛利 = 0 的费比：判断促销是否值得
- **健康度综合分**：见第六节评分模型

## 六、渠道健康度评分模型（核心引擎）

把"逐行读表"升级为"一眼排序"。5 个维度，每维度 0–100 分，加权得总分，映射 A/B/C/D 评级。

### 6.1 五维度定义

| 维度 | 权重 | 子指标 | 计算逻辑 |
|------|------|--------|---------|
| **产出力** | 25% | GMV、商家实收、销量 | 当期值 / 全渠道均值，标准化到 0–100 |
| **盈利力** | 25% | 毛利率、毛利贡献占比 | 毛利率 vs 全渠道中位数 + 贡献占比 |
| **效率力** | 20% | ROI、费比、边际 ROI | ROI vs 阈值（ROI<1 直接低分） |
| **增长力** | 15% | GMV 环比、商家实收环比、CTR 趋势 | 环比为正且加速得高分 |
| **风险力** | 15% | 退款率、退款率趋势、达成缺口 | 退款率超阈值扣分，趋势恶化加倍扣 |

### 6.2 评级映射

| 总分 | 评级 | 含义 | 默认动作 |
|------|------|------|---------|
| ≥85 | A | 优质渠道，应加投 | 预算 +10%~20%，复制经验 |
| 70–84 | B | 健康但有余量 | 维持，针对性优化短板维度 |
| 55–69 | C | 风险或低效 | 诊断根因，设定 2 周改善目标 |
| <55 | D | 拖累整体 | 收缩预算，启动专项复盘 |

### 6.3 评分规则的可解释性

每个评级必须能拆解到子指标。例："抖音评 C，因效率力 42 分（ROI 6.5 低于阈值 8）+ 风险力 51 分（退款率 18% 且环比 +3pp）"。**评分不是黑箱，是诊断的入口。**

## 七、从"描述"到"决策"的转化规则

这是整套体系的灵魂。下表展示如何把现有 callout 式描述升级为决策级结论。

| 现状（描述层） | 升级后（决策层） |
|---------------|----------------|
| "抖音毛利率最高（75.2%）" | "抖音毛利率 75.2% 但体量仅占 12%，盈利力 A 但产出力 C；若将抖音预算从 30 万提至 45 万，按当前 ROI 6.5 测算月增量毛利 +18 万，优先级 P1" |
| "拼多多退款率偏高" | "拼多多退款率 22% 超 15% 阈值且环比 +4pp，集中在 X 类目 Y 单品；建议本周下架 Y 单品并复核质检，预期退款率回落至 16%，月减损 6 万，优先级 P0" |
| "唯品毛利率垫底" | "唯品毛利率 8% 低于盈亏平衡线 12%，连续 2 月恶化；边际 ROI 已 0.8（<1），建议收缩预算 50% 并迁移至京东，预期月净毛利 +9 万，优先级 P0" |
| "优先拆解促销与补贴" | "天猫促销期间 ROI 4.2 低于日常 7.1，增量 GMV 80 万但增量毛利仅 5 万，费比盈亏平衡需 GMV +120 万；建议下次促销降费比 3pp 或不做，优先级 P2" |

每条结论的固定结构：`现象 + 量化影响 + 根因(置信度) + 建议动作 + 预期收益 + 优先级`。

- 渠道×品类矩阵分析
- 退款归因专题

## 十、成功标准

报告体系是否"够深入"，用以下标准衡量（建议作为季度复盘 KPI）：

1. **决策采纳率**：报告建议被业务采纳执行的比例 ≥ 60%
2. **预警前置率**：渠道恶化在 D 评级前被预警的比例 ≥ 70%
3. **结论可追溯**：每条结论可下钻到原始数据与计算逻辑（100%）
4. **预算优化收益**：基于报告做的预算调配，季度净毛利提升 ≥ 8%
5. **报告阅读时长**：L1 ≤ 3 分钟决策、L2 ≤ 15 分钟诊断
