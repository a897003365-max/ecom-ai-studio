# AnalyticsPage 信息架构重排方案

> 参考：[帆软"全平台运营总览"模板 20001294](https://app.fanruan.com/templates/20001294)
> 目标：将本地 `AnalyticsPage` 从"平铺 KPI + 表格"重排为"五层递进"结构，对齐帆软信息架构
> 范围：**仅前端渲染顺序与视觉分区调整**，不改数仓、不改钉钉字段、不新增数据源
> 硬约束：钉钉是全渠道权威源（天猫/京东/抖音/拼多多已覆盖），保持深色科技风 + 荧光绿主色

## 1. 帆软模板信息架构（Ground Truth）

从帆软模板描述反推的模块顺序（从上到下、按业务优先级递进）：

```
L1 销售业绩 → L2 客户价值 → L3 投放成本 → L4 流量转化 → L5 风险管理 → L6 平台趋势
```

## 2. 本地现状 vs 目标结构

| 层 | 帆软模块 | 本地字段（钉钉 totals） | 现状 |
|---|---|---|---|
| L1 | GMV、净销售额 | `gmv`、`netRevenue` | ✅ 已有，但和其他 KPI 平铺 |
| L2 | 件单价、客单价 | ❌ 无对应字段 | ⚠️ 钉钉表未覆盖，PowerBI 可补 |
| L3 | 投放金额、ROI、费率 | `spend`、`feeRate` | ⚠️ 有费额和费比，ROI 缺 |
| L4 | 访客数、成交客户数、支付转化率 | `addToCart` | ⚠️ 只有加购，访客/成交/转化在 PowerBI [06-旗舰店流量数据.pq](../migration/power-query-m/original/06-旗舰店流量数据.pq) |
| L5 | 退款金额、退款金额占比 | `refund`、`refundRate` | ✅ 已有 |
| L6 | 平台销售分析 | `monthlyOverview.daily` | ✅ 已有 `MonthlyOverview` 组件 |

**结论**：钉钉数据可直接支撑 L1/L3（部分）/L5/L6；L2/L4 需要 PowerBI mart 补充。

## 8. 阶段二/三的位置

- **阶段二（数据口径补齐）**：把 L2/L3/L4 的 placeholder 换成真实数据

  - `visitor/order/conversion`：从 PowerBI [06-旗舰店流量数据](../migration/power-query-m/original/06-旗舰店流量数据.pq) 派生

- **阶段三（抖音数据源）**：**已通过钉钉全渠道表覆盖**，本次不再单独接入 Excel 或千川 API。
  - 需确认：钉钉「全渠道数据表」中"抖音"渠道字段的**完整度**（是否包含推广花费、访客等）
  - 如钉钉抖音字段仅覆盖 GMV/回款/退款而缺推广细节，则**再启动阶段三**（用户 2B 选项）
